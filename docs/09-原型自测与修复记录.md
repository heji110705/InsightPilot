> 对象：`docs/prototype/index.html`（GitHub Pages 上的 5 屏可点原型）。
> 方式：Playwright + Chromium 真实点击，1440×900 与 390×844 两个视口；首轮 20 条用例、复测 23 条。

## 2 根因

### 2.1 主因：结果只写进侧栏，主区没有出口

提交函数做完两件事就结束了：

```js
st.turns.unshift({ q: v, r: A[v], mine: true });
save(st); render();
say('已记入本次会话（本机存储，刷新后仍在）…');
```

`render()` 只渲染右侧 300px 侧栏里的一行 —— 10.5px 字号、灰色、`63 本 · 5.71s`。
主区（用户视线中心）**没有结果容器**；真正的"结果页"是独立的第 3 屏，而第 3 屏是写死"精装书"的静态稿，任何提问都不会把它驱动起来。

所以用户的真实体验是：输入问题 → 点"提问" → 页面几乎没变 → 结论"没有显示结果"。**这跟取数成功与否无关，是渲染路径缺了一段。**

### 2.2 次因 A：`state()` 把 localStorage 当唯一真相，写失败就静默丢数据

```js
function state(){ const st = read(); if(st) return st; const f = fresh(); save(f); return f; }
```

`read()` 读不到（存储被禁用 / 配额满 / JSON 损坏 / 内嵌 iframe 被隔离）就返回一份**全新的种子数据**；提交时改的是这个临时对象，`save()` 失败后 `render()` 又读回种子 —— 刚提交的条目凭空消失。而 `say()` 不看 `save()` 的返回值，照样报"已记入本次会话（本机存储，刷新后仍在）"。

**页面在说谎**：数据没存，提示说存了。复现方式是把 `Storage.prototype.setItem` 改成抛异常，再问一句，列表纹丝不动、提示照旧。

这类环境不是边角料：无痕窗口、Safari 隐私模式、配额写满、跨域 iframe、以及**WorkBuddy/IDE 的内嵌预览面板**——用户当时就是在这种面板里打开的。

### 2.3 次因 B：焦点在输入框时，← → 会切屏

```js
document.addEventListener('keydown', e => {
  if(e.key === 'ArrowRight') show((cur + 1) % 5);   // 没排除输入态
});
```

在输入框里按方向键移动光标 —— 界面直接跳屏。实测按一次 ← 从第 1 屏跳到第 5 屏。用户刚点完"提问"、焦点还在输入框，随手一个方向键，视觉上就是"结果没了"。

### 2.4 次因 C：输入法选词的回车被当成提交

```js
qin.addEventListener('keydown', e => { if(e.key === 'Enter') submit(); });
```

没判断 `e.isComposing`。中文输入法按回车确认候选词，拼音串被当成问题提交，必然未命中 —— 用户看到的是"答不了"，不是结果。

### 2.5 次因 D：入口的点击成本与死路

- 首页 3 个示例 chip 只把文字填进输入框，不提交，第一次用的人会以为点了没反应。
- 第 3 屏"你可能还想问"给的 3 个问题（平装有多少本 / 精装与平装差多少 / 精装里评分最高）**全都不在可答集合里**，点了必然"答不了"。
- 空输入只有红边框，没有一句"先写一句要问的问题"。

## 3 改法

| 问题 | 改法 |
|---|---|
| 主区无结果 | 新增**结果卡**：问题 + 状态 pill + 大数字 + 结论句 + 结果表 + 可展开复制的 SQL + 口径脚注 + 操作按钮；答不了时给"答不了 + 为什么 + 三个可点替代问法" |
| 只 3 条可答 | 内置问答 3 → **6 条**，全部由 `data/warehouse.sqlite` 实查（见下），并加 12 条别名问法 |
| 存储当真相 | 改成**内存是唯一真相**，localStorage 只负责跨刷新；写失败降级并在侧栏与提示里明说"刷新即丢"，不再谎称已保存 |
| 输入框里切屏 | keydown 先判断 `INPUT/TEXTAREA/contentEditable` 与 `isComposing`，带修饰键也不响应 |
| 输入法回车 | `if (e.isComposing \|\| e.keyCode === 229) return;` |
| chip 只填词 | 点 chip 直接提交出结果；答不了卡片里也放可点的替代问法 |
| 跨标签不同步 | 监听 `storage` 事件，另一标签写库后本页重渲染 |
| 清空依赖 confirm | 改页内二次确认（第一次点变"确认清空？"，3.2s 自动回退） |
| 死按钮 | 第 3 屏"复制 SQL"接剪贴板（含 `execCommand` 降级），其余按钮给 toast 说明；第 4 屏"按默认口径出结果"直接跳第 3 屏 |
| favicon 404 | 内联 SVG data URI |
| 画板被撑高 | 只有结果卡展开且停在首屏时给画板加高，切到其它屏恢复固定高度，版式不散 |

## 4 六条内置问答（数字全部实查，可复核）

| 问题 | 结果 | SQL 要点 |
|---|---|---|
| 精装书有多少本 | 63 本（占 250 本的 25.2%） | `COUNT(*) WHERE binding='精装'` |
| 各分类平均价格 | 12 个分类，艺术设计 ¥100.20 最高、诗歌散文 ¥20.86 最低 | `GROUP BY category` + `AVG(price)` |
| 评论最多的书是哪本 | 陆犯焉识 17 条（我的阿勒泰 16、美的历程 15） | `fact_comment JOIN dim_book` |
| 平装有多少本 | 181 本（72.4%） | `COUNT(*) WHERE binding='平装'` |
| 精装与平装的平均价格差多少 | 精装 ¥61.01 / 平装 ¥40.72，差 ¥20.29（高 49.8%） | `GROUP BY binding` |
| 精装书里评分最高的是哪本 | 悉达多 9.46（20 人评分） | `ORDER BY rating_avg DESC, rating_count DESC` |

耗时字段只有跑过完整链路的 3 条保留真实值（5.71s / 5.48s / 缓存 0.04s），其余 3 条标"未计时"——不编造延迟。

### 4.1 补的一层：实体模板（作者 / 分类 / 装帧 × 多少本）

第一版只有 6 条精确匹配，随手问一句"老舍有几本"就撞墙——而这句在库里是有答案的（3 本：四世同堂、茶馆、骆驼祥子）。所以加了一层模板匹配，把"能答"从 6 句扩到一整片：

- 实体表全部由 `warehouse.sqlite` 查出后内联：**186 位作者**（含各自书目/分类/定价）、**12 个分类**（本数 + 均价）、**8 种装帧值**。
- 只接**计数问法**（"多少本 / 几本"），且一旦句子里出现"平均 / 价格 / 评分 / 评论 / 销量 / 最高 / 占比 / 趋势"就**不进模板**——这类聚合问题交给完整链路，宁可答不了，也不给一条看着对的错数。
- 命中后照样出结果卡：大数字 + 书目/分类明细表 + 带参数的 SQL + 口径脚注，元信息里标"实体模板：作者维度"。

实测：

| 问法 | 结果 |
|---|---|
| 老舍有几本 | 3 本（四世同堂 / 茶馆 / 骆驼祥子） |
| 鲁迅有几本 | 6 本 |
| 阿加莎·克里斯蒂有几本 | 4 本（自动忽略「[英]」国别前缀） |
| 文学小说有多少本 | 139 本，均价 ¥43.77，评分最高《海风中失落的血色馈赠》9.64 |
| 精装16开有几本 | 1 本（装帧长尾也能答） |
| 鲁迅的书平均价格多少 | 答不了（聚合问法不进模板，边界如实暴露） |
| 骑行有多少本 | 答不了（库里没有这个实体） |

## 6 顺带修掉的口径错误

原第 3 屏写"占全部在架图书的 12.9%""扫描行数 494"，与仓库对不上：`dim_book` 实际 250 行，63/250 = **25.2%**，扫描 **250 行**。已改成与库一致。这个数字只出现在原型（含作品包里的副本），简历与 PRD 未引用。

## 7 仍然缺的

- 能答的范围是"6 条示例 + 作者/分类/装帧计数"，**不覆盖**按作者/分类的均价、趋势、排名这类聚合问题；问到了会明确回"答不了"。
- 第 3 屏仍是静态设计稿（精装书那条），不是由结果卡驱动的动态页。
- 云服务上次在确认框里被拒，数据仍只在本机；跨设备看记录做不到。

## 8 面试演示动线（3 分钟）

1. 点"精装书有多少本" → 结果卡：63 本 + 结论 + 表格（15 秒）
2. 展开"生成的 SQL" → 讲"答案必须可复核，不是模型口述数字"（30 秒）
3. 问"老舍有几本" → 3 本并列出书名，讲"实体识别 + 模板取数，覆盖全库 186 位作者"（30 秒）
4. 问"精装与平装的平均价格差多少" → ¥20.29/本，讲口径（30 秒）
5. 随手问一个库里没有的（如"骑行有多少本"）→ 答不了 + 替代问法 → 讲"不猜"的边界（30 秒）
6. 切第 3/4/5 屏 → 复核视图、口径默认策略、评测表（45 秒）
