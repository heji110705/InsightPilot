# InsightPilot 演示录屏脚本（3 分钟版）

> 用途：投递时作为"可验证交付"的第二个证据（第一个是简历，第二个是这个链接，第三个是 PRD）。
> 目标不是炫技，是让 HR / 面试官在 3 分钟内确认三件事：**能跑、答得对、答不了会说答不了**。

---

## 录制前准备（5 分钟）

| 项 | 做法 |
|---|---|
| 启动服务 | `cd InsightPilot && python -m uvicorn app.api.server:app --port 8000` |
| 打开页面 | 浏览器访问 `http://127.0.0.1:8000`，窗口调到 **1440 × 900**，F11 全屏 |
| 预热一次 | 先跑一遍「精装书有多少本」，确认能出结果，然后**刷新页面**（保证录到的是首次耗时，而不是缓存命中） |
| 关干扰 | 关闭微信 / QQ 通知，隐藏浏览器书签栏，桌面只留浏览器窗口 |
| 录制工具 | Windows：`Win + G`（Xbox Game Bar）或 OBS；输出 1080p、30fps |
| 口播 | 不一定要出声。**录屏 + 字幕**更适合在 Boss 上直接发（对方常静音看） |

## 分镜表

| 时间 | 画面动作 | 字幕（建议逐字打） | 这段要证明什么 |
|---|---|---|---|
| **0:00–0:12** | 停在首页，鼠标划过输入框与三个示例问题 | 「InsightPilot：中文提问自助取数。答案附 SQL 与结果集，可复核。」 | 一句话说清是什么 |
| **0:12–0:18** | 鼠标移到首页底部那行边界提示 | 「答不了的会直接说答不了——比如趋势类问题，这个库算不出来。」 | **先亮边界**，区别于"什么都敢答"的 demo |
| **0:18–1:00** | 输入 `精装书有多少本` → 回车 → 等结果 | 「执行 5.7 秒。结论 63 本；下面是它生成的 SQL，可以复制去复核。」 | 主链路能跑通 + 可复核 |
| **1:00–1:10** | 滚动到口径脚注；点击「复制 SQL」 | 「每个答案都带口径脚注：取哪个字段、含不含变体。」 | 可信度来源 |
| **1:10–1:25** | 再问同一句，显示 0.04s | 「同一个问题再问一次，命中缓存，0.04 秒。」 | 有工程优化，不是裸调 API |
| **1:25–1:50** | 输入 `各分类平均价格` | 「"均价"有歧义。它不追问，直接采用默认口径并标注，用户可以换。」 | **产品判断**：追问会打断用户 |
| **1:50–2:10** | 输入 `最近三个月的销量趋势` | 「这类问题它会拒绝：库里日期字段几乎单值，物理上算不出趋势。它不会编一条曲线给你。」 | 诚实边界 = 最高辨识度的一段 |
| **2:10–2:35** | 打开 `/eval` 页 | 「60 道题、4 种配置、每种跑两轮。答对率 18.3% 到 50.0%，两轮波动 0–3.4 个百分点。」 | 有评测体系，不是"我觉得好用" |
| **2:35–2:50** | 停在消融表，鼠标划过 `no_critic` 行 | 「关掉自检也是 50%，说明这一环在现有题集上还没收益，这一条我记进了待办。」 | **敢报不利结论**，这一句最容易让面试官记住 |
| **2:50–3:00** | 切到 GitHub 仓库页，停 3 秒 | 「代码、评测报告、PRD 都在仓库里。」 | 留一个可验证的入口 |

## 三条口播原则

1. **先给数字，再给解释。** 不要"我这里做了一个……"，直接"63 本，5.7 秒，SQL 在下面"。
2. **主动说一处不足。** 全程只夸的 demo 会被当成 PPT；主动说"这个库不支持趋势"和"自检暂时没收益"，可信度立刻不一样。
3. **不超过 3 分钟。** HR 看完简历后的耐心窗口大约就是 3 分钟，超过就会被划走。

## 交付方式

| 渠道 | 怎么发 |
|---|---|
| Boss 直聘 | 简历发完后补一句："另外有个 3 分钟的录屏，方便的话可以看一下：[链接]" |
| 邮件 | 正文一行 + 附件 PDF（PRD）+ 录屏链接 |
| 面试现场 | 直接本地起服务演示，比录屏更有说服力；录屏作为兜底 |

> 录屏文件建议命名 `InsightPilot-演示-3min.mp4`，控制在 20MB 以内，放网盘或 GitHub Release，不要直接发原始大文件。
